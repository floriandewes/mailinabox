What it is

Your own mail service provider, in a few easy steps.

Trixie Mail (software id TrixieMail) is an agentic fork of Mail-in-a-Box. It turns a fresh Debian 13 (Trixie) machine into a working mail appliance— sort of like making your own Gmail, but one you control from top to bottom.

You don’t need to be a systems expert. There are no user-configurable setup options beyond a few install questions (or an install.conf). It just works.

Why this fork

Built for Debian, languages, and agents.

Three first-class differences from upstream Mail-in-a-Box—grounded in this repository.

Debian 13 for security

TrixieMail installs only on Debian 13 (Trixie). The installer aborts on other systems. Upstream Mail-in-a-Box tracks Ubuntu 22.04; this fork deliberately moves the stack to Debian packages— including Dovecot 2.4, PHP 8.4, and current Nextcloud—so you stay on a modern, security-focused base.

Do not use the upstream one-line installer at mailinabox.email; that tracks the Ubuntu release.

Internationalization

The control panel ships with i18n: gettext / Flask-Babel catalogs and a language switcher for English, German, French, Spanish, Italian, Portuguese, Dutch, and Polish. Internationalized domain names (IDNs) are supported for mail domains; SMTPUTF8 is not.

Human & agentic installs

Interactive setup still asks for timezone, admin email, hostname, IP, and password. Agents write install.conf and run setup/start.sh --noninteractive— no TTY, no hanging prompts, missing keys abort immediately. Consent for identity and secrets stays explicit.

In the box

A complete mail appliance.

TrixieMail installs and configures the pieces you need—and no more.

  • Mail — SMTP (Postfix), IMAP (Dovecot), webmail (Roundcube), Exchange ActiveSync (Z-Push)
  • Contacts & calendar — CardDAV / CalDAV via Nextcloud
  • Protection — SpamAssassin; optional greylisting (off by default); fail2ban; ufw
  • DNS — nsd with SPF, DKIM, DMARC, DNSSEC, DANE TLSA, MTA-STS, and SSHFP records
  • TLS — Let’s Encrypt certificates for HTTPS and mail services
  • Ops — duplicity backups, munin monitoring, daily health checks, control panel + REST API

Your box can host mail for multiple users and domains, and can serve simple static websites over HTTPS— or point domains elsewhere with custom DNS in the control panel. See the security guide for the threat model.

Get it

Install on a fresh Debian 13 machine.

Requirements: dedicated Debian 13, x86_64/i686, ≥512 MB RAM (768 MB+ recommended), public IPv4, outbound TCP 25, and a domain you control. Suggested hostname: box.<your-domain>.

On the machine:

sudo apt update
sudo apt install -y git
git clone https://github.com/quantenland-ai/trixiemail
cd trixiemail
sudo setup/start.sh

Setup asks for timezone, admin email, hostname, public IP (if needed), and the first account password. When it finishes it prints Your Trixie Mail is running. and the control panel URL (https://box.example.com/admin).

This port sets up a new box; it does not upgrade an older Mail-in-a-Box Ubuntu data directory. To change answers later: sudo trixiemail or sudo mailinabox.

Agents install without a TTY: collect answers, write config, then run noninteractive setup.

  1. Ask the user for PRIMARY_HOSTNAME, EMAIL_ADDR, EMAIL_PW, TIMEZONE, and confirm PUBLIC_IP (or auto). Never invent an admin address from the hostname.
  2. Write install.conf from conf/install.conf.example (gitignored; holds the password).
  3. Run sudo setup/start.sh --noninteractive.
  4. Report admin email, password (once, if generated), control panel URL, and that DNS still needs setting.
cp conf/install.conf.example install.conf
# edit install.conf — never commit it
sudo setup/start.sh --noninteractive

Hostname need not resolve before install. Incomplete config with --noninteractive exits with an error instead of hanging.

TrixieMail is open source under the project LICENSE. Setup uses Let’s Encrypt; accept the Let’s Encrypt Subscriber Agreement before you begin.

Status

Current release 26.11.1

Versioning is YY.MM[.N], aiming for a release about every 1–2 months. Release history lives in CHANGELOG.md. An experimental uninstaller (setup/uninstall.sh) can reverse install side effects; mail data is kept by default.

Why build this

Decentralize mail. Keep it honest.

  • Make deploying a good mail server easy.
  • Promote decentralization, innovation, and privacy on the web.
  • Have automated, auditable, and idempotent configuration.
  • Support headless / agent-driven installs without sacrificing explicit user consent for identity and secrets.
  • Not make a totally unhackable, NSA-proof server.
  • Not make something customizable by power users.

The Code of Conduct supersedes the goals above.

Help
